# Naming Law

> The ISO naming convention for ShopnoOS - deterministic, enforced, never manual.

---

## The Rule

Every ISO produced by this repository is named from build variables. No human constructs the name, no one renames after the fact. The name is a machine-readable statement of exactly what is inside the file.

**Format:**

```
<DISTRO_ID>-<DISTRO_VERSION>-<DISTRO_EDITION>-<DISTRO_FLAVOR>-<DISTRO_ARCH>-<BUILDDATE>[-<DISTRO_HARDWARE>].iso
```

**Implemented in:** `scripts/lib/iso-name.sh` - sourced by `build.sh`, `stamp-iso.sh`, and `sign-iso.sh`. The ISO name is never constructed anywhere else. If you find a script constructing an ISO filename by hand, that is a bug.

---

## Field Reference

| Field | Source | Format | Example |
|-------|--------|--------|---------|
| `DISTRO_ID` | `brand/identity/name.env` | Lowercase alphanumeric, hyphens allowed | `shopno-os` |
| `DISTRO_VERSION` | `brand/identity/name.env` | Digits and dots only | `1.0`, `1.1`, `2024.01` |
| `DISTRO_EDITION` | `profiles/<n>/profile.env` | Lowercase, matches `editions/` directory name | `core`, `desktop`, `pro` |
| `DISTRO_FLAVOR` | `profiles/<n>/profile.env` | Lowercase, matches `flavors/` directory name, or `none` | `gnome`, `kde`, `xfce`, `none` |
| `DISTRO_ARCH` | `profiles/<n>/profile.env` | Debian architecture string | `amd64`, `arm64` |
| `BUILDDATE` | Generated at build time | `YYYYMMDD` | `20250301` |
| `DISTRO_HARDWARE` | `profiles/<n>/profile.env` | Lowercase, matches `hardware/` directory name - **omitted when `generic`** | `nvidia`, `vm` |

### Notes on individual fields

**`DISTRO_ID`** - used as the prefix of every ISO and artifact filename. Changing it mid-project renames all ISOs, breaks mirror URLs, and invalidates any hardcoded references. Only change this with a deliberate rebrand, and update `docs/branding-guide.md` at the same time.

**`DISTRO_VERSION`** - must match the regex `^[0-9]+(\.[0-9]+)*$`. The build system enforces this in `brand.sh` and will refuse to build if the version is malformed. No `v` prefix, no `-dev` suffix, no pre-release labels in the version string. The git tag carries the `v` prefix; the ISO filename does not.

**`DISTRO_FLAVOR`** - when the edition has no desktop environment (i.e. the `core` edition), the flavor is `none`. This is a literal string in the filename, not an empty field.

**`BUILDDATE`** - generated by `iso-name.sh` at build time using the system date. Two builds of the same profile on the same day produce the same filename. If you need to distinguish them, use `--output-dir` to separate them, or track by the `BUILD_ID` field in `/etc/os-release` and `build-manifest.json`.

**Hardware suffix** - only appended when `DISTRO_HARDWARE` is not `generic`. A generic build has no hardware suffix. This keeps the common case clean and the hardware variant clearly identifiable.

## Examples

```
shopno-os-1.0-desktop-xfce-amd64-20250301.iso
shopno-os-1.0-desktop-gnome-amd64-20250301.iso
shopno-os-1.0-desktop-kde-amd64-20250301.iso
shopno-os-1.0-core-none-amd64-20250301.iso
shopno-os-1.0-pro-gnome-amd64-20250301.iso
shopno-os-1.0-pro-kde-amd64-20250301.iso
shopno-os-1.0-pro-gnome-amd64-20250301-nvidia.iso
shopno-os-1.0-desktop-xfce-amd64-20250301-vm.iso
```

Reading any of these filenames tells you unambiguously: which distribution, which version, which edition, which DE, which architecture, when it was built, and what hardware variant it targets. No README required to know what an ISO is.

## Associated Artifact Names

The checksum and signature files are derived from the ISO name by `iso-name.sh`. They are never named independently.

```
shopno-os-1.0-desktop-gnome-amd64-20250301.iso
shopno-os-1.0-desktop-gnome-amd64-20250301.iso.sha256
shopno-os-1.0-desktop-gnome-amd64-20250301.iso.sha512
shopno-os-1.0-desktop-gnome-amd64-20250301.iso.gpg
```

The functions that produce these names:

| Function | Returns |
|----------|---------|
| `iso_name` | Full ISO filename with `.iso` extension |
| `iso_stem` | ISO filename without extension |
| `iso_checksum_filename sha256` | ISO filename + `.sha256` |
| `iso_checksum_filename sha512` | ISO filename + `.sha512` |
| `iso_signature_filename` | ISO filename + `.gpg` |

## Why This Matters

### Reproducibility

The filename encodes the build inputs. If you have two ISOs with different names, they were built from different inputs. If they have the same name, they were built from the same profile on the same day - and their checksums should match unless something changed in the upstream apt mirror between builds.

### Mirror structure

The release mirror organises files by version and expects deterministic names. `scripts/release/publish.sh` uses `iso_name()` to construct mirror paths. Manual renaming breaks publish.

### Traceability

When a bug report comes in referencing `shopno-os-1.0-desktop-xfce-amd64-20250301.iso`, you know immediately: version 1.0, desktop edition, XFCE flavor, amd64, built on 2025-03-01. You can check out the exact tag, rebuild, and reproduce the issue without asking the reporter for more information.

---

## Enforcement

`iso-name.sh` is the single source of truth. It is:

- Sourced by `scripts/build/build.sh` before any build step
- Sourced by `scripts/build/stamp-iso.sh` when embedding metadata
- Sourced by `scripts/release/sign-iso.sh` when naming checksum and signature files

The lint script `tests/lint/check-no-hardcoded-names.sh` scans all scripts for inline ISO name construction and fails CI if it finds any. If you need the ISO name in a new script, source `iso-name.sh` and call `iso_name()` - do not construct it yourself.

---

## Common Mistakes

| Mistake | Consequence |
|---------|-------------|
| Renaming the ISO after build | Checksum and signature files still reference the original name - verification breaks |
| Constructing the filename inline in a script | Different scripts can drift out of sync; the name will be wrong on version bumps |
| Using a `v` prefix in `DISTRO_VERSION` | Build fails - `brand.sh` rejects non-numeric version strings |
| Leaving `DISTRO_FLAVOR` empty for `core` | Produces a malformed filename like `shopno-os-1.0-core--amd64-...` - set it to `none` |
| Two builds of the same profile on the same day | Same filename - distinguish by `BUILD_ID` in `/etc/os-release`, not by filename |
